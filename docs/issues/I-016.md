# I-016 退出保护

编辑文件让 Tab 出现未保存圆点，然后按 `⌘Q` 或点红色关闭按钮：App 直接退出，修改丢失。

- 菜单里只有 `{ role: "quit", shortcut: "mod+q" }`；`decideGuard` 只保护关 Tab、`⌘⇧W` 和切换文件夹。
- `nsh 0.4.0` 的 `.nsh/types/nsh/*.d.ts` 里没有找到窗口关闭或退出钩子（`beforeunload` / close request）。

## 做法

1. 先查 `nsh 0.4.0` 的 `nsh/desktop` 和 `nsh` 是否有关闭/退出拦截（类型定义、`~/.nsh` 下的文档和运行时）。有就用它接上 `decideGuard` 和现有的 `id:unsaved-changes-dialog`。
2. 没有的话：
   - 把 `⌘Q` 换成自己的菜单项和快捷键 `actions.quit()`，先走未保存保护，然后用 `process.exit`（`capabilities.process.exit` 已授权）退出。
   - 窗口关闭按钮由 `scripts/finder_bridge.m` 处理（它已经 swizzle 了宿主 delegate）：注入 `windowShouldClose:` / `applicationShouldTerminate:`，有未保存修改时拒绝关闭，并通知 JS 弹出确认框。JS 与原生之间的状态传递方式（例如 JS 通过宿主事件告诉原生「当前是否 dirty」）写进 `DESIGN.md「术语与边界」`。改 `scripts/` 需要按 AGENTS.md 第 6 条找另一个模型独立审查。
3. 两条路都走不通时，把卡片改成 `external-blocked` 并写清缺的 NSH API。

## verify

`nsh check && nsh test --trace`，新增 Red 测试：`quitting with unsaved edits asks first`（无头可测 `actions.quit` 走保护；原生关闭按钮需要用户同意后用 `--target macos` 手测）。
